# VKJ-002. Описание v1 не допускает `null` у коллекций, которые продукт возвращает пустыми как `null`

**Серьёзность:** средняя
**Версия:** Vikunja v2.6.0
**Компонент:** описание API первой версии
**Окружение:** официальный образ `vikunja/vikunja:2.6.0`, PostgreSQL 18, стенд из `docker/docker-compose.yml`

## Суть

Описание первой версии API объявляет поля-коллекции обязательно непустыми по типу:

```json
{ "type": "array" }
```

Продукт возвращает в них `null`, когда коллекция пуста. Это ожидаемое поведение сериализации в Go: нулевое значение среза или карты превращается в `null`, а не в `[]` или `{}`.

Затронуто как минимум тринадцать полей на основных сущностях:

| Сущность | Поля |
|---|---|
| задача | `labels`, `assignees`, `attachments`, `reminders`, `related_tasks`, `reactions` |
| проект | `views`, `max_permission` |
| представление | `bucket_configuration`, `filter`, `filter.order_by`, `filter.sort_by` |
| пользователь | `settings.extra_settings_links` |
| команда | `members` |

Отдельно поле `max_permission`: описание объявляет его перечислением `[0, 1, 2]`, а тип прав в продукте сериализует своё состояние «неизвестно» как `null`, которого перечисление не допускает.

## Почему это дефект описания

Описание второй версии API, генерируемое продуктом из собственного кода, объявляет те же самые поля правильно:

| Поле | v1 | v2 |
|---|---|---|
| `labels` | `"array"` | `["array", "null"]` |
| `assignees` | `"array"` | `["array", "null"]` |
| `attachments` | `"array"` | `["array", "null"]` |
| `reminders` | `"array"` | `["array", "null"]` |

Поведение продукта одинаково в обеих версиях. Различается только описание, и правильное из двух то, которое новее.

## Влияние

Клиент, сгенерированный из описания первой версии на строго типизированном языке, падает на разборе любой задачи без меток, без исполнителей и без вложений, то есть на самом обычном случае. Обходной путь для пользователя один: объявлять каждое поле-коллекцию необязательным вручную, игнорируя сгенерированные типы.

## Воспроизведение

```bash
python reproduce.py
```

Скрипт создаёт пользователя, проект и задачу без меток, после чего печатает фактический ответ рядом с обоими описаниями.

## Что чинить

Проставить нуллевость в аннотациях первой версии так же, как это уже сделано во второй. Альтернатива, которая чинит обе версии сразу: инициализировать срезы и карты пустыми значениями перед сериализацией, чтобы продукт отдавал `[]` и `{}`.
