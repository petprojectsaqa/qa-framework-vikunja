Каждая находка воспроизводится за две минуты и не требует доверия к автору: в папке лежит скрипт на Python без зависимостей, который ничего не импортирует из фреймворка и показывает результат сам.

## Как прогнать воспроизведение

Стенд должен быть поднят:

```bash
docker compose -f docker/docker-compose.yml up -d --quiet-pull
```

Дальше одна команда на всё:

```bash
py scripts/verify_findings.py
```

Или одна находка:

```bash
py scripts/verify_findings.py VKJ-007
```

Запускатель находит скрипты относительно себя, поэтому работает из любой папки, сам проверяет, отвечает ли стенд, и печатает по строке на находку. Если не нашёл ни одного скрипта или стенд молчит, он скажет об этом вслух. Цикл в командной строке так не умеет: несовпавший шаблон даёт пустой вывод, неотличимый от полного успеха.

Каждый отдельный скрипт запускается и сам по себе, зависимостей у него нет и из фреймворка он ничего не импортирует:

```bash
py docs/findings/VKJ-007-label-update-verb/reproduce.py
```

Он печатает рядом то, что обещает описание продукта, и то, что продукт отвечает. Код возврата ноль означает, что находка подтвердилась.

**Про имя интерпретатора.** В PowerShell на Windows команда `python` ведёт на заглушку из Microsoft Store и не запускается, настоящий интерпретатор зовётся `py`. В Git Bash и на Linux работает `python`.

## Проверка на дубликаты

Перед тем как о чём-то сообщать, трекер продукта просмотрен на совпадения. Результат:

- **VKJ-001 частично пересекается с [issue #3316](https://github.com/go-vikunja/vikunja/issues/3316)**, закрытой 29 июля 2026 года. Там та же причина была устранена во второй версии API. Описание первой версии осталось как было, поэтому находка остаётся в силе, но сообщать о ней нужно как о продолжении закрытой issue, а не как о новом дефекте.
- Остальные восемь совпадений в трекере не имеют. Проверялись запросы по описанию API, формату ошибок, статусам 401, 403, 404 и 405, нуллевости полей и сбоям разбора у сгенерированных клиентов.
- Версия 2.6.0 на момент проверки последняя, то есть всё найденное относится к актуальному выпуску.

## Статус: в трекер не отправлено

Находки сознательно не заведены в трекер продукта. Причина в требованиях проекта к вкладу, описанных ниже: они разумны, но соблюдение их для девяти сообщений стоит больше времени, чем даёт пользы прямо сейчас. Короткие черновики готовы и лежат в бэклоге.

На ценность самих находок это не влияет. Каждая подтверждается запуском одной команды на чистом стенде, поэтому читателю не нужно ничьё стороннее одобрение, чтобы убедиться в них.

## Правила проекта по вкладу

У Vikunja в `CONTRIBUTING.md` есть отдельный раздел про участие ИИ, и он задаёт рамку для любого сообщения им:

- сгенерированные баг-репорты не принимаются, сообщать можно только о том, что воспроизвёл сам;
- текст держать коротким, сгенерированная проза обычно слишком длинная;
- участие ИИ раскрывать;
- уязвимости только проверенные на актуальной версии и через их процедуру.

Поэтому подробные разборы в этой папке предназначены читателю репозитория, а не трекеру. В трекер идут короткие сообщения, и перед отправкой каждое воспроизведение прогоняется руками.

## Про VKJ-006

Находка касается границы авторизации, поэтому по принятому здесь правилу подробности не публикуются, пока сопровождающие продукта не ответят. В наборе она зафиксирована двумя тестами в `tests/api/test_outsider_disclosure.py`, помеченными как ожидаемо падающие: они формулируют позицию, не ломая сборку, и превратятся в неожиданный успех, если продукт изменит поведение.

Серьёзность низкая: утечки содержимого нет, и такое поведение встречается в API часто и иногда выбрано сознательно. Приватное уведомление здесь не про опасность, а про порядок.

## Как это устроено

Известные расхождения записаны в базовую линию (`src/vikunja_qa/contracts/baseline.py`) с причиной и ссылкой на отчёт. Набор работает в строгом режиме: расхождение, которого нет в базовой линии, роняет тест, который его вызвал. Базовая линия существует только для того, чтобы уже описанное не заглушало новое, и может только сокращаться. Модульный тест проверяет, что ни одна запись не появилась ради тишины.

Ожидаемо падающие тесты используются для позиций, которые набор высказывает, но не считает доказанными дефектами. Утверждать текущее поведение там было бы неправильно: это заморозило бы спорное поведение в наборе как желаемое.
