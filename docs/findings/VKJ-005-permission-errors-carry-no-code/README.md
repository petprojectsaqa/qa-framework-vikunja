# VKJ-005. Ошибки доступа не несут доменного кода, по которому клиент их переводит

**Серьёзность:** средняя
**Версия:** Vikunja v2.6.0
**Компонент:** обработка ошибок, обе версии API
**Окружение:** официальный образ `vikunja/vikunja:2.6.0`, стенд из `docker/docker-compose.yml`

## Суть

В продукте есть числовой доменный код ошибки, по которому клиенты подбирают перевод сообщения. Отсутствующие объекты возвращают осмысленные коды. Отказы в доступе не возвращают ничего полезного:

| Запрос | Статус | Доменный код | Сообщение |
|---|---|---|---|
| `GET /api/v1/tasks/{чужой}` | 403 | `0` | You don't have the permission to see this |
| `GET /api/v1/tasks/{отсутствующий}` | 404 | `4002` | This task does not exist |
| `GET /api/v1/projects/{чужой}` | 403 | `0` | You don't have the permission to see this |
| `GET /api/v1/projects/{отсутствующий}` | 404 | `3001` | This project does not exist. |
| `DELETE /api/v1/tasks/{чужой}` | 403 | `0` | Forbidden |
| `GET /api/v2/tasks/{чужой}` | 403 | поля нет | You don't have the permission to see this |

Первая версия отдаёт ноль, вторая не отдаёт поле вовсе. При этом в коде второй версии есть отдельная забота о переносе доменного кода в ответ, и рядом комментарий, объясняющий, что без переноса клиенты читают ноль. То есть механизм есть, но на путь отказа в доступе он не распространяется, потому что переносить нечего.

## Влияние

Отказ в доступе это одна из самых частых ошибок, которые видит живой пользователь. Именно её клиент перевести не может: нулевой код не отличим от «кода нет», а по тексту сообщения переводить нельзя. В интерфейсе на любом языке, кроме английского, пользователь получает английскую строку от сервера.

Дополнительно страдает различение случаев. Все отказы приходят с нулём, поэтому клиент не может отличить «нет прав на объект» от «нет прав на действие» и показать разные подсказки.

## Шаги воспроизведения

```bash
python reproduce.py
```

Скрипт заводит двух пользователей, создаёт проект и задачу от первого и опрашивает их вторым, печатая коды рядом.

## Ожидаемый результат

У ошибки доступа есть собственный ненулевой доменный код, как у ошибки отсутствия.

## Фактический результат

Ноль в первой версии, отсутствие поля во второй.

## Что чинить

Завести доменные коды для отказов в доступе и пропустить их через тот же перенос, который уже сделан для остальных ошибок второй версии.

## Связанный тест

`tests/api/contracts/test_error_codes.py::test_a_refusal_carries_no_usable_code`. Тест утверждает текущее поведение намеренно, чтобы исправление не прошло незамеченным: когда коды появятся, он покраснеет и сообщение скажет, что находка, вероятно, закрыта.
