# VKJ-009. Ручки, отдающие двоичные данные, описаны как возвращающие JSON

**Серьёзность:** низкая
**Версия:** Vikunja v2.6.0
**Компонент:** описание API, обе версии
**Окружение:** официальный образ `vikunja/vikunja:2.6.0`, стенд из `docker/docker-compose.yml`

## Суть

Несколько операций отдают не JSON, а изображение, картинку с кодом или архив выгрузки. В описании у них объявлена структурированная схема ответа, из-за чего потребитель описания ожидает объект.

| Операция | Что отдаёт на самом деле |
|---|---|
| `GET /api/v2/avatar/{username}` | изображение |
| `GET /api/v2/user/settings/totp/qrcode` | изображение с кодом |
| `GET /api/v2/user/export` | архив выгрузки |
| `GET /api/v1/{username}/avatar` | изображение |

## Влияние

Сгенерированный клиент попытается разобрать двоичный ответ как JSON и упадёт. Обход это не трудность, но обнаруживается он только во время выполнения, а не при чтении описания.

Ошибка того же рода, что и остальные расхождения описания: продукт ведёт себя разумно, описание врёт.

## Воспроизведение

Видно в отчёте обхода `tests/api/test_generated_sweep.py`: вид нарушения `not JSON` с пояснением, какой тип пришёл вместо структуры.

## Что чинить

Объявить этим операциям соответствующий тип содержимого, например `image/png` или `application/zip`, вместо схемы объекта.

## Связанный тест

Ловится контрактной проверкой в транспортном слое. В базовой линии записано как `VKJ-009`.
