# VKJ-016. Отзыв CalDAV-токена сообщает об успехе, когда ничего не отозвано

[English](README.md) | Русский

**Серьёзность:** средняя
**Версия:** Vikunja v2.6.0
**Компонент:** CalDAV-токены, `DELETE /user/settings/token/caldav/{id}`
**Окружение:** официальный образ `vikunja/vikunja:2.6.0`, стенд из `docker/docker-compose.yml`

## Суть

Отзыв CalDAV-токена отвечает **«The token was deleted successfully»** в двух случаях, когда никакой токен не отозван:

```
DELETE /api/v1/user/settings/token/caldav/999999999   (такого токена нет)
  -> 200 {"message":"The token was deleted successfully."}

DELETE /api/v1/user/settings/token/caldav/<токен алисы>   (от имени боба)
  -> 200 {"message":"The token was deleted successfully."}
```

После второго вызова токен Алисы остаётся в её списке и продолжает открывать её календарь. Вторая версия API ведёт себя так же и отвечает 204.

## Влияние

Важная половина здесь не в несуществующем идентификаторе. `DELETE`, идемпотентный относительно того, чего уже нет, это защитимое решение, и так отвечают многие API.

Важна вторая половина, чужой токен. Отзыв учётных данных это действие про безопасность, и продукт прямым текстом подтверждает его, пока эти данные продолжают работать. Человек, отзывающий токен из устаревшего списка, из второй сессии или со страницы, открытой до смены учётной записи, получает сообщение, что токена больше нет. Он есть. CalDAV-токен это постоянный пароль ко всему календарю, поэтому расхождение между сказанным и сделанным здесь ровно то, на которое администратор и будет полагаться.

Повышения привилегий нет: Боб не может отозвать токен Алисы, и проверка, которая ему это запрещает, работает. Не хватает сообщения о том, что он этого не сделал.

## Шаги воспроизведения

1. Зарегистрировать две учётные записи, Алису и Боба.
2. От Алисы выпустить CalDAV-токен: `PUT /api/v1/user/settings/token/caldav`.
3. От Боба удалить его по идентификатору.
4. Посмотреть список токенов Алисы и обратиться этим токеном к `/dav/`.

`reproduce.py` в этой папке делает всё это и печатает каждый ответ:

```bash
py docs/findings/VKJ-016-caldav-token-revocation-false-success/reproduce.py
```

## Ожидаемый результат

Отзыв сообщает об успехе только тогда, когда что-то отозвано. Для токена, принадлежащего другой учётной записи, ожидается 404, как продукт уже отвечает для других объектов, существование которых он не подтверждает.

## Фактический результат

200 с явным подтверждением в обоих случаях, и чужой токен продолжает работать.

## Что чинить

Сообщать о том, что произошло: отвечать 404, если удаление не совпало ни с одной строкой вызывающей учётной записи. Условие владения в коде уже знает ответ, его игнорирует только сам ответ.

## Как найдено

Не тестом, написанным под это. Порождаемый межверсионный обход ошибок спрашивает у каждой операции, описанной обеими версиями, про несуществующий идентификатор и сравнивает два ответа. Именно на этой операции версии разошлись в том, случилась ли вообще ошибка, что и привело к паре учётных записей.

## Связанный тест

`tests/api/contracts/test_error_codes.py::test_revoking_a_token_that_was_not_revoked_says_so`, помечен как ожидаемо падающий. Позиция зафиксирована, сборку не ломает, и тест превратится в неожиданный успех, когда ответ начнёт соответствовать действию.
