# VKJ-010. Неудачная загрузка файла возвращает код 200

[English](README.md) | Русский

**Серьёзность:** высокая
**Версия:** Vikunja v2.6.0
**Компонент:** загрузка вложений при недоступном объектном хранилище
**Окружение:** официальный образ `vikunja/vikunja:2.6.0`, хранилище файлов в S3-совместимом MinIO, стенд из `docker/docker-compose.yml`

## Суть

Если объектное хранилище недоступно, загрузка вложения не удаётся, но ответ приходит с кодом **200 OK**. Признак неудачи спрятан в теле:

```
HTTP/1.1 200 OK
{"errors":[{"message":"failed to save file: failed to upload file to S3: operation error S3 ..."}]}
```

Дополнительно ответ приходит только через **28 секунд**: клиент всё это время держит соединение.

## Влияние

Код ответа это первое и часто единственное, на что смотрит клиент. Библиотеки поднимают исключение по коду, сгенерированные клиенты ветвятся по нему, очереди и повторы решают по нему судьбу задачи. Двухсотый код здесь означает, что вызывающая сторона считает файл сохранённым.

Последствие для пользователя прямое: интерфейс показывает успех, вложение исчезает, и никакой ошибки человек не видит. Данные теряются молча, а это худший вид потери, потому что о ней не узнают вовремя.

Двадцать восемь секунд удержания соединения усугубляют: при массовой загрузке пул соединений выбирается целиком.

## Что работает правильно

Стоит отметить, потому что это показывает, что изоляция зависимостей в продукте в принципе есть. При том же отключённом хранилище создание задачи, которому файлы не нужны, отработало за одну десятую секунды и вернуло 201. То есть отказ хранилища не валит продукт целиком, проблема именно в отчёте о результате.

## Шаги воспроизведения

1. Поднять стенд.
2. Остановить контейнер хранилища: `docker compose stop minio`.
3. Загрузить вложение к задаче через API.
4. Посмотреть на код ответа и на тело.
5. Вернуть контейнер: `docker compose start minio`.

Тест `tests/resilience/dependencies/test_object_storage.py` делает это целиком и сам восстанавливает стенд.

## Ожидаемый результат

Неудачная загрузка отвечает кодом из диапазона ошибок, предпочтительно 502 или 503, поскольку причина во внешней зависимости.

## Фактический результат

Код 200 с описанием ошибки в теле.

## Что чинить

Возвращать код ошибки, когда сохранение файла не удалось. Отдельно стоит сократить ожидание: двадцать восемь секунд это, вероятно, сумма повторов клиента S3, и её стоит ограничить.

## Связанный тест

`tests/resilience/dependencies/test_object_storage.py::test_a_failed_upload_says_so_in_its_status_code`, помечен как ожидаемо падающий. Позиция зафиксирована, сборку не ломает, и превратится в неожиданный успех, когда код ответа исправят.
