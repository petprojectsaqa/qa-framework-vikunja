# Стенд

[English](README.md) | Русский

Восемь контейнеров, поднимаются одной командой. Система под тестом это Vikunja 2.6.0.

## Запуск

```bash
docker compose up -d --quiet-pull
python ../scripts/check_stand.py
```

Второй шаг обязателен. Он дожидается готовности каждого сервиса и проходит один настоящий пользовательский путь целиком, поэтому зелёный результат действительно что-то значит. Прогон тестов без него запускать нельзя: `docker compose up` возвращает управление раньше, чем приложение готово принимать запросы.

Остановка с удалением данных:

```bash
docker compose down -v
```

## Что где слушает

| Сервис | Порт | Зачем |
|---|---|---|
| vikunja | 3456 | система под тестом |
| postgres | 15432 | прямые запросы для проверки целостности |
| redis | 16379 | хранилище ключей и счётчики ограничения частоты |
| minio | 19000, 19001 | объектное хранилище файлов и его консоль |
| mailpit | 18025, 11025 | перехват почты, API для чтения писем и SMTP |
| приёмник вебхуков | 18080 | запись исходящих вызовов |
| prometheus | 19090 | сбор метрик приложения |
| grafana | 13000 | панель наблюдения, вход анонимный |

**Почему порты именно такие.** Все они лежат ниже 49152. В Windows диапазон динамических портов резервируется под Hyper-V, и попадание в него даёт отказ привязки сокета с невнятным сообщением про права доступа. Проверить занятые диапазоны можно так:

```bash
netsh int ipv4 show excludedportrange protocol=tcp
```

## Настройки стенда и почему они такие

**Ограничение частоты выключено.** Иначе параллельный прогон упрётся в собственный лимит. Тесты самого ограничения поднимают отдельный профиль с включённым.

**Пороги для маршрутов без авторизации подняты отдельно.** Это не то же самое, что общий выключатель. У продукта есть пол в десять запросов в минуту на адрес для маршрутов до авторизации, и он **намеренно игнорирует общий флаг**, о чём прямо сказано комментарием в исходниках:

> pre-auth routes need a floor even with the global limiter off, which is the default

Каждый создаваемый аккаунт стоит трёх таких вызовов: регистрация, подтверждение адреса и вход. При пороге по умолчанию набор смог бы создавать три аккаунта в минуту, чего не хватит даже на разогрев. Поэтому `VIKUNJA_RATELIMIT_NOAUTHLIMIT` поднят на стенде, вместе с порогами для базовой авторизации и обновления токена. В профиле для тестов ограничения частоты они остаются настоящими.

**Файлы уходят в объектное хранилище, а не на диск.** Это более длинный путь в коде продукта и он ближе к боевой установке.

**Почта включена и уходит в перехватчик.** Следствие этого важное: Vikunja требует подтверждения адреса перед первым входом, если почтовик настроен. Тесты проходят это подтверждение настоящим путём, читая письмо из перехватчика. Полный круг занимает около четырёх десятых секунды, поэтому чёрный ход через подмену статуса в базе не нужен.

**Служебный API продукта включён секретом.** Он даёт очистку всех таблиц и наполнение конкретной таблицы. Используется строго в двух случаях: однократная очистка перед прогоном и подготовка состояний, недостижимых через публичный API. Обычные данные готовятся только обычными вызовами.

**Разрешены вызовы на немаршрутизируемые адреса.** Приёмник вебхуков живёт в частной сети Compose, без этого флага продукт откажется к нему стучаться.

**CalDAV включён**, это значение по умолчанию у продукта. Это вторая дверь к тем же данным, и набор проверяет, что обе двери сходятся.

## Спецификации

Обе версии API отдают свои описания на живом инстансе:

| Версия | Путь | Формат | Путей |
|---|---|---|---|
| v1 | `/api/v1/docs.json` | Swagger 2.0 | 126 |
| v2 | `/api/v2/openapi.json` | OpenAPI 3.1.0 | 133 |

Спецификации забираются с инстанса, а не из репозитория продукта, чтобы проверялась ровно та версия, которая поднята.

## Диагностика

Логи приложения:

```bash
docker compose logs vikunja -f
```

Интерфейс Docker Desktop даёт то же самое мышкой, плюс терминал внутрь контейнера и обзор файлов. Для проверок устойчивости к отказам оттуда же удобно гасить отдельные контейнеры руками.

Почта видна глазами на `http://localhost:18025`, объектное хранилище на `http://localhost:19001` с учётными данными `minioadmin` и `minioadmin`, панель наблюдения на `http://localhost:13000`.

Записанные вебхуки читаются так:

```bash
curl http://localhost:18080/_recorded
```

Каждый тест шлёт вебхуки на собственный путь вида `/hook/<идентификатор теста>`, поэтому записи не перемешиваются при параллельном прогоне.
